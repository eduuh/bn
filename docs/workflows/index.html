Overview

bn's workflow, as built rather than as designed

bn describes a nine-stage pipeline that carries a task from pickup to learn. Three of those stages are driven by code. The gap between the two is not decay — it is the most useful thing to understand about the system, and this set of notes is organised around it.

The shape of the claim

Read crates/bn-core/src/pipeline/stage.rs and you get a clean state machine: pickup → investigate → plan → consensus → execute → validate → critique → ship → learn. Nine variants, ordered so that Ord and next() follow the flow. It reads like a workflow engine.

It is not one. The enum encodes no exit predicate for any stage. A stage changes when something calls stage::transition, and only three stages have machinery that decides when they are finished — the SWEPT set, whose completion is their backlog entry reaching Done. crates/bn-core/src/pipeline/sweep.rs:40

The load-bearing fact

This is deliberate, not unfinished. Dropping the sweep at execute is a written decision: after execute, validate / critique / ship each have their own machinery, and driving them from the sweep too would give one step two owners. crates/bn-core/src/pipeline/sweep.rs:36-40

And the default lane is not the pipeline at all

A second gap sits underneath the first. bn dispatch — the command that actually starts work — does not enter the nine-stage pipeline by default. Its default lane is ship-solo, a single-session workflow; the pipeline is behind an environment variable, $BN_DISPATCH_PIPELINE=1. crates/bn-cli/src/cmd/dispatch.rs · docs/config.md

So there are two answers to "what runs when I start a task", and the codebase says plainly that this is intended: Stage::default_skill and dispatch_skill_name answer different questions, and "both are right; they are not the same question." crates/bn-core/src/pipeline/stage.rs:96-102

How these notes were produced, and what that means for trust

Five agents read non-overlapping slices of the repo and reported with file:line citations and an explicit "could not verify" list. Everything stated as fact here carries a citation to the code it came from. Where the agents could not confirm something, this set says so rather than smoothing it over — those admissions are collected at the foot of each note.

Reading these safely

Line numbers were accurate when the notes were written and will drift. Treat a citation as "this claim came from here", not as a permanent address — and re-check the file before relying on a number in a decision.
