Note 06

The surfaces a human actually touches

Three doors into one core: a terminal, a browser, and a scheduler. They share an implementation by construction — the web UI shells out to the same bn binary you type — and they all read and write the same event log.

The CLI

One flat namespace of roughly a hundred top-level commands. Internally it is ten #[command(flatten)] group enums, and that split is purely mechanical — it keeps a ~100-variant enum from blowing libtest's 2 MiB thread stack in debug builds. The group names never appear in help. crates/bn-cli/src/cli.rs:28-35, :1364

Two commands one letter apart

bn review is the plan-approval gate. bn reviews is the PR review queue. They are unrelated. cli.rs:433, :684

The real interactive surface is tmux

There is no TUI. The bindings are the UI: prefix j = bn jump, prefix Tab = next agent, prefix C-o = bn tat (switch project), prefix C-a = bn doctor --pick, prefix a / prefix b = add a todo or blocker without leaving the pane. config/workflow/tmux.conf — grep the bind for a key, or run prefix ?

The web dashboard

bn serve is a launcher only — it resolves the sibling bn-web binary and execs it, gated on cfg.web_enabled_here(). Default bind is 127.0.0.1:7770; --lan binds 0.0.0.0. crates/bn-cli/src/serve.rs:35, :85 · docs/config.md

There is no authentication

A token is generated and persisted 0600 to <config_dir>/web-token, but the server never requires it — on loopback or on --lan. The trust boundary is the bind address plus a trusted network; external exposure is meant to go through an authenticated dev tunnel. So bn serve --lan puts a fully mutating API — dispatch, kill agents, land PRs, edit skills — on 0.0.0.0 with no credential. crates/bn-web/src/auth.rs:1-8 · routes.rs:112-113, :236-237

Reads fold bn-core in-process; writes shell out to bn --json, so the browser and the terminal share one implementation rather than two. Every write — accepted and rejected — appends a web_action event, which the SSE tailer fans back into the activity feed. crates/bn-web/src/audit.rs:1-10

Mutating routes include /api/dispatch, /api/agents/{target}/{send,relaunch,kill,answer,instruct}, /api/land, /api/reviews/{id}, /api/attention/{id}, skills and agent-def CRUD, /api/cron/run, and the per-repo orchestrate and pool/warm actions. The router also nests MCP at /mcp and /mcp/orchestrate — the same untokened surface. routes.rs:115-190, :232-233

Most of the UI is hidden by default

A fresh bn serve shows three rail entries: Today, Cron, Settings. Console, Nodes, Staff, Attention, Automation, Goals, Repos, Insights, Notes, Skills, Agents, Handoff and Research all need ?experimental=<key> or a toggle on /settings. The routes resolve either way — they are simply not advertised. bn-web/ui/src/components/shell/Rail.tsx:33-39 · lib/nav.ts

Attention and today: two different things

Scheduling

Twenty-two [[cron]] entries in config/crons.toml. The canonical schedule language is systemd OnCalendar — everywhere, including macOS. crates/bn-core/src/crons.rs:46-49

Several ticks fold multiple jobs behind one timer to cut timer churn: tick-5m runs tools-reconcile, coord-tick, attention-sync, tmux-reconcile and tmux-keylog; tick-10m runs auto-review-trigger, attention-auto-trigger and agent-supervise; tick-15m runs main-sync, auto-review-poll and cron-health. Each child still records its own cron_run event, so per-job rows survive. cmd/job_registry.rs:64-80

bn run <job> checks the native registry first — roughly 38 jobs are compiled-in Rust functions — and only falls back to config/jobs/<job>.sh for the seven not yet ported. job_registry.rs:16-58

One manifest, three very different installs

Installation is the same command everywhere — bn cron register, idempotent — but what it produces diverges sharply:

PlatformWhat gets created
systemdA .service + .timer pair per job. OnCalendar passes through verbatim; network = true adds After/Wants=network-online.target. cron_gen.rs:28-58
launchdA plist per job. launchd has no OnCalendar parser, so the subset the manifests use is translated into StartInterval / StartCalendarInterval. is_loaded asks the supervisor rather than the filesystem, because a crash-looping job leaves its plist behind. cron_gen.rs:1-4, :246 · launchd.rs:67-70
WindowsExactly one scheduled task: a WSL keepalive running bn run ensure-tmux at logon and every 30 minutes. The tmux server it starts keeps WSL alive, and systemd inside WSL runs everything else. config/jobs/windows/install.ps1:3-8
Reclamation is deliberately never on a cron

The wt-cleanup and fleet-reap crons were removed so that nothing automated can ever delete a branch, remove a worktree, or kill a tmux session under active work. There is a written "Do NOT re-add these". The jobs still exist for manual bn wt cleanup / bn run fleet-reap. config/crons.toml:17-25

Gating is layered: a machine runs cron for every repository it has cloned unless its [machine] table narrows repos or sets cron = false; then [[cron]].only_on limits registration and [jobs.only_on] limits execution. A machine that has switched cron off reports not_enabled rather than erroring. config/jobs/README.md:22-30

Cost

Two units, deliberately labelled apart:

  • AIC (AI Credits) — the real metered bill, from totalNanoAiu on each Copilot session. null for raw-Claude runs, which carry no AIC.
  • $ (API-equiv) — a benchmark, not a bill: tokens against a cache-aware price table. On a Claude Code session nearly every prompt token is a cache read (~10× cheaper) or a cache write (1.25–2× dearer), so each of the four buckets is charged at its own rate.

crates/bn-core/src/cost/mod.rs:1-20

Two disjoint event sources are summed: agent_session events (real token capture, synced across machines) and the staff_run ledger (estimated scheduled spend). They are disjoint because staff runs dispatch headless and never pin a session, so nothing double-counts. cost/mod.rs:28-32

GET /api/cost calls the same rollup and serializes it verbatim — the ?by= parameter is accepted and ignored, because the view already carries every breakdown and the dashboard switches dimension client-side with no refetch. crates/bn-web/src/cost.rs:20-27

A day in the life

# Morning: what is waiting, and what to do about it
bn next                                   # ranked cross-repo actions
bn attn                                   # three-lane attention board
bn today list                             # agent-proposed tasks from cron findings
bn today accept s2

# Ground the work, then cut a worktree for it
bn task add "fix flaky pool-slot reconcile test" --repo bn
bn task enhance T14                       # SMART-gate it
bn dispatch T14 --repo bn --name pool-reconcile-flake

# Punch in and set the branch's goal (now inside the new worktree)
bn in "pool reconcile flake" --tag dev
bn goal "make the pool-slot reconcile test deterministic"
bn add done-when "test passes 20x in a row"
bn add todo "reproduce locally with a seeded clock"

# Work. Capture as you go, without leaving the pane (prefix a / prefix b)
bn q "leases.json holder can outlive every agent that held it"
bn done t1
bn notes "root cause: reconcile ran before the tmux server exited"
bn learned "reconcile the pool-slot ledger before trusting leases.json"

# Ship
bn build
bn autopush "fix: deterministic pool-slot reconcile"
bn pr https://github.com/owner/bn/pull/1234
bn ingest                                 # fold the diffstat back into the note

# Close the loop
bn reflect "should have checked the lease ledger before the test"
bn out
bn wrap
bn cost --by category --window 1

Things that will mislead you

  • bn dispatch's default lane is ship-solo, not the nine-stage pipeline. The pipeline is behind $BN_DISPATCH_PIPELINE=1. crates/bn-cli/src/cmd/dispatch.rs · docs/config.md
  • bn today runs an LLM agent by default. It is not a static list read, and it costs something each time.
  • bn cost's dollar figure is not a bill. Only AIC is metered; $ is a public-list-price benchmark.
  • macOS never sees OnCalendar. It is translated at generation time, so a schedule expression that works on Linux may not survive translation.
  • Windows schedules one task, not many. If that keepalive is not running, nothing else runs either.
  • bn cron retire exists for a reason. The watchdog reads health from the event log, so a renamed job's old failures otherwise read as an ongoing outage. cli/cron_cmd.rs:24-34
