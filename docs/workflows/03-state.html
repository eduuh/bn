State & history

Entire remembers sessions. Workspan executes work.

Session capture is not a task queue. Workspan retains actionable task state, execution gates, plans, and operational evidence; Entire owns captured agent sessions and checkpoints.

One owner for each kind of state

Tasks are independent of branches

The file and Forge task providers remain supported. A task may bind to a worktree while being executed, but the branch is not its identity or a prerequisite for its context. Do not silently substitute local storage when the selected remote provider fails. Complete a task with workspan task do <id> only when its acceptance criteria are met.

Keep task documents concise: what the outcome needs, concrete blockers, necessary scope decisions, and the next action. Do not copy the full session transcript or maintain a second chronological handoff log.

Plans and execution evidence

Use workspan plan init, workspan plan path, and workspan plan status rather than guessing an artifact directory. The active plan contains ordered steps and observable done-when criteria. Execution metadata is separate from the plan body; neither requires a session note.

Command-run success is historical evidence for a particular invocation and checkout, not a claim that later edits passed. Re-run affected gates after source changes or a rebase. Session capture does not replace these verification checks.

Capture privacy

Repository onboarding requires Entire with an explicitly approved private checkpoint destination. Run the selected harness's setup helper and confirm entire status. Missing tools, failed privacy checks, or an unapproved destination block onboarding. Do not upload existing history, enable other projects, or change hosting as a migration side effect. See the setup reference.

Existing data

Historical branch-note files remain untouched as archives. Workspan no longer requires them, advertises note MCP tools, or maintains a duplicate session ledger. Existing configuration and task-storage paths, including historical BN_* names, remain compatible; their names are not a reason to move or delete user data.
