Note 03

Dispatch, isolation and reclamation

Two different things in this codebase are called a lease, over the same directory, with different lifetimes and different owners. Separating them is the single biggest comprehension win in the dispatch layer — most confusion downstream traces back to conflating the two.

The two leases

Agent lease

Durable, atomic ownership of an agent-bearing worktree, stored in agent-leases.json. A record is {key: (repo, branch, worktree), session_id, harness, kind, tmux_target, acquired_at}. crates/bn-core/src/agent/lease.rs:163, :288

It protects one invariant: one agent per checkout. Conflict is detected on key.worktree alone rather than the whole key, because two branches co-owning one directory is the exact bug it exists to prevent. lease.rs:316-323, :345, :363

The lifecycle is acquire → commit → release, with no renewal and no heartbeat. A lease is authoritative if its tmux target still has a live pane, or if it is younger than AGENT_LEASE_STARTING_GRACE_SECS = 30. lease.rs:13, :308 · crates/bn-cli/src/agent_lease.rs:46

Acquisition is a two-phase reservation. begin_agent_lease writes the new owner while holding the file lock and returns an AgentLeaseReservation whose Drop restores the entire prior registry unless commit() is called. Dispatch reserves, reaps prior owners, launches the window, then commits — rolling back if the launch fails. lease.rs:201-246, :324 · cmd/dispatch.rs:1719-1780

Placement is validated before the lock, as policy rather than contention: the stow-source worktree/<repo>/main hosts no agent at all, and _pool/1 belongs to the controller. lease.rs:89, :99, :138

Pool lease

A slot tenancy in <worktree>/<repo>/_pool/leases.json: {branch, holder, pid, at, boot_id, comparison_slot}. This one is renewed, but only on relaunch — touch_dispatch_lease re-stamps pid, timestamp and boot id so a relaunch's kill does not look like abandonment. crates/bn-cli/src/wt_pool.rs:100, :1252

The worktree pool

A slot is <root>/worktree/<repo>/_pool/<n> — a warm checkout with dependencies and build cache intact, reused by many branches in turn. Pool size is derived from the directories that exist, never declared: DEFAULT_POOL_SIZE = 4 including the reserved slot, growing one at a time up to MAX_POOL_SIZE = 16. wt_pool.rs:1-17 · crates/bn-core/src/pool.rs:34, :215

The acquisition ladder

acquire_slot runs the whole pick-and-persist under lock_leases, in this order:

  1. Reclaim prior-boot leases
  2. adopt_occupied_slots — claim slots a live agent is in that the ledger never named wt_pool.rs:471
  3. live_branch_slot — idempotent same-branch hit
  4. pick_slot — lowest idle
  5. reclaim_stale(AnyDeadHolder)
  6. reclaim_leaked_leases
  7. Grow the pool
  8. Create or switch_into_slot, then persist

Afterwards ensure_spare_slot warms one ahead. wt_pool.rs:776, :1295

Reclamation is proof, not guess

lease_abandoned requires all three: not occupied, and not dirty, and (holder dead or older than a five-minute grace). "Occupied" is itself a union of three oracles — the lease registry, @bn_*-stamped tmux windows, and any live pane rooted in the checkout. pool.rs:193 · wt_pool/reclaim.rs:123 · agent_lease.rs:300, :373

prune only removes over-size or orphan slots, never leased, dirty or in-use ones; destroy requires explicit --include-* flags. Releasing a slot is a warm_reset — detach, discard changes, clean -df — so the checkout itself survives. wt_pool.rs:352, :585, :603

Supervision

bn reads the harnesses' own on-disk transcripts and writes nothing of its own. Claude at ~/.claude/projects/<encoded-cwd>/<sid>.jsonl, Copilot at ~/.copilot/session-state/<id>/events.jsonl. crates/bn-core/src/agent/supervise.rs:290, :524

HealthConditionDerived or stamped
StartingLaunch record exists, no transcript yet; retired after 20 minstamped
ActiveIdle < 5 minderived
IdleIdle ≥ 5 minderived
StuckIdle ≥ 15 minderived
Ended15 min silent and no hosting tmux windowstamped

Ended needs two facts rather than one for a concrete reason: a transcript stays readable for QUIET_SECS = 1800, so without the second condition every finished agent posed as stuck for half an hour. supervise.rs:46, :226-238, :342 · agent/parse.rs:14

Steerability is a separate question from health

resolve_channels joins agents to windows on a five-tier evidence ladder — lease, @bn_session_id, worktree path, @bn_repo/@bn_branch, then window name — and only the branch-keyed tiers are allowed to degrade to Ambiguous. Matching on window name alone turned out to be effectively dead code. agent/channel.rs:1-25, :177

"Stuck" for a controller was a narrower, pane-text question — a classifier over the pane tail returning McpLoading, InteractivePrompt, WorkingIdle or IdleWithWip, plus a separate probe measuring cumulative output tokens to tell a stalled agent from one that simply had not produced a turn yet. Both were driven by the orchestrate daemon and were removed with it; only the StuckLane shape itself survives. agent/stuck.rs

Reclamation policy

fleet_gc::classify is pure, and evaluates in a fixed order: the orchestrator is sacrosanct (not even --force touches it) → a stale reason (pr-merged, pr-closed, worktree-gone, window-gone) → then the guards Attended > Working > Uncommitted > Grace. crates/bn-core/src/fleet_gc.rs:~208

Approvals and autonomy

approval.rs is a pure decision function over a parsed dialog plus approvals.toml, evaluated in a fixed safety order:

  1. Default deny.
  2. A question-menu is never auto-answered, at any setting — checked before the master switch. approval.rs:272
  3. Deny rules win unconditionally.
  4. The chosen option must exist in the dialog. approval.rs:323

Policy is off by default even when the file exists; rules are substrings rather than regexes on purpose; trust menus need their own trust_menu = true; and a malformed file degrades to deny-everything. approval.rs:89-93, :126, :159-177

Autonomy has two axes: PolicyScope = Orchestrated | Dispatched | All, and PolicyCtx.trusted — the --yolo trust contract, carried only by orchestrated coding and ship items. Research and scout lanes are deliberately dispatched non-trusted. Every decision, approved or escalated, is appended to state_dir/approvals.jsonl along with the options it faced. approval.rs:36, :188, :230 · cmd/agent_approve.rs:19-70, :81

Things that will mislead you

  • --yolo raises the plan-review gate rather than bypassing it — "autonomy costs a plan review instead of buying its way out of one". And it is silently dropped when the seed came from an external URL, because that is a prompt-injection → command-execution path. cmd/dispatch/policy.rs:~85 · cmd/dispatch.rs:989-1009
  • A pool lease's pid is the caller's parent — a tmux server or login shell that outlives every agent it launches. Gating reclamation on pid liveness therefore frees nothing in normal use, which is exactly why the second occupancy-based sweep exists. pool.rs:184-189 · wt_pool/reclaim.rs:1-8
  • boot_id is how the pool survives a reboot — a lease tagged with a prior boot's id is provably dead even if the pid was recycled. Linux and WSL only. wt_pool.rs:155 · pool.rs:108
  • pid_alive used to return true off Linux, which silently disabled every abandonment decision on macOS. wt_pool.rs:405-412
  • A slot's memory must be truncated at lease start. Harnesses key session history on the directory, so typing claude in a returned idle slot resumed the previous tenant's work. slot_lease_started_at exists so resume ignores history older than the current lease. wt_pool.rs:1239
  • A pooled agent has no branch in its path, so worktree_repo_branch deliberately returns None rather than ("bn", "_pool") — otherwise every pooled agent shares one meaningless identity and the reaper skips exactly the agents holding the fleet. fleet_gc.rs:~270
  • A full pool queues onto the repo's orchestrate run rather than cutting a cold worktree; the old unconditional fallback grew the disk without bound. cmd/dispatch.rs:52-88
  • The tmux window name is presentation, not identity — yet dispatch is forced to use orchestrate::tmux_window_name anyway, because every orchestrate consumer reconstructs <repo>:<sanitized branch>. A prettier name made the daemon misclassify its own lanes as dead. cmd/dispatch.rs:1701-1710
  • Slot 1 never rotates. It is detached at the base — git refuses to check main out twice — and is shared by the controller and by you. wt_pool.rs:~1005 · lease.rs:84-89
  • A copilot-only dispatch window is hardcoded until 21:00. Before that, any harness choice is overridden to Copilot. cmd/dispatch/policy.rs:25-60
  • Fleet::running_count() is agents − ended, not agents.len(). Capacity supervises with stuck_mins = 0, and reading "no window ⇒ finished" there would retire live agents. supervise.rs:269, :342

Not verified

  • AgentKind::Hosted has no distinct execution path that could be found in bn-cli — it appears only in validation, the catalog badge and the web UI. AgentLeaseKind::Today calls the day's session "hosted", so the two may be related, but no runtime link was confirmed.
  • Whether a cron fires the auto-approval sweep periodically. Two call sites were found (cmd/orchestrate.rs:4089, cmd/routes/automation.rs:238) but the schedule was not traced.
  • What --with-main comparison slots are actually used for, beyond "detached primary-branch comparison tree".
  • How session outcomes are assigned on ingest. outcome: "quiet" is one value and completed_status maps "failed" → SessionStatus::Failed, but the full set was not enumerated — so the account above is stronger on the live side (Ended) than on the ingest side.
  • AgentTransport has exactly one implementation (TmuxTransport). The nvim-hosted second implementation hinted at by @bn_nvim_sock does not exist yet, so how a non-pane agent would be steered is unverified.
